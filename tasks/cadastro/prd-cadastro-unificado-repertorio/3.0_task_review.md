## 3. Observações

1. **Verificação de ISWC duplicado dentro da transação** (Handler.cs:213-217): segura (rollback em falha), mas idealmente seria pré-transação para evitar abrir/fechar conexão desnecessária. Não é bloqueante.
2. **Soma autoral verificada duas vezes**: uma no `Validator` (linha 65) e uma no handler (linha 177). Redundância defensiva aceitável, a segunda é pós-criação das titularidades.
3. **Titularidades adicionadas sem `AddAsync` explícito**: as titularidades são criadas com `TitularidadeAutoral.Criar()` mas não chamam `_xxxRepository.AddAsync`. Como o handler chama `_obraRepository.Update(obra)` (linha 183) para cada titularidade, o EF deve fazer track por navegação. Se a relação não estiver configurada como cascade, isso pode ser um problema em testes de integração — **não impacta testes unitários mockados**.
4. **Cobertura de 17 testes** cobre todos os fluxos exigidos: sucesso, pendente, indisponibilidade, rollback, regras de negócio, auditoria/outbox.
